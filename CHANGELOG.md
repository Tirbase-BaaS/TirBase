## [Unreleased]

### Added
- **Alerts and notification framework (CC-17):** AGPL `tirbase_gateway::alerts` adds the runtime's alerting engine — the AGPL `AlertNotifier` trait plus routing, deduplication, delivery, retries, escalation, acknowledgement, dead letters and a delivery audit — and Apache-2.0 `tirbase-notify` adds the connector surface closed vendor plugins can implement without linking the runtime: the `NotifyTransport` interface, the alert message model, secrets by reference, deterministic retry arithmetic, on-call rotation maths and the generic email (SMTP session with `AUTH PLAIN`, CRLF/ dot-stuffing, sanitised headers), webhook (deterministic JSON body, `Idempotency-Key`, HMAC-SHA256 signature, status classification) and console connectors. Alerts are unique on `(tenant, dedup_key)` and deliveries on `(alert, channel, address, level)`, so raising the same event again returns `RaiseOutcome::Duplicate` and pages nobody a second time; a delivery row is written before the transport is called and only marked delivered after it accepts, so a crash between send and record re-sends with the same delivery id and deduplication key. `RetryPolicy` schedules bounded exponential backoff with key-derived jitter (a restart computes the same deadline), a retriable failure stays `pending` with its attempt count and last error visible in `deliveries()` and the `retry` audit row, and a permanent failure or exhausted budget moves the delivery to `alert_dead_letters` with the reason. A rule with `escalate_after_secs` and `max_level > 1` pages the next on-call level once the deadline passes without an acknowledgement (audited as `escalated`, or `escalation_unrouted` when the rotation is broken instead of dropped), and `acknowledge` is idempotent and stops it. Routing picks a site-specific rule over a global one, the lowest rule id among equals, resolves each role through the on-call rotation at the alert's own observation time, addresses person-directed channels to the on-call member, collapses duplicate recipients, and records an alert with no matching route as `unrouted` rather than discarding it. Channels carry a `SecretRef` name only — `FileSecretStore` rejects absolute names, `..` and symlinks escaping its root, and no secret value reaches the database, an audit row or a `Debug` rendering; `AlertsConfig` denies unknown fields, so an inline `secret` is a parse error. `Alert::from_excursion` bridges CC-11 notifications with their deduplication id intact. AGPL `tests/alerts.rs` proves the three acceptance conditions — no duplicate page on a repeated event (including a different alert id with the same key), a failed delivery retried with backoff and visible then dead-lettered when exhausted or permanent, and an unacknowledged critical alert escalating at its deadline while an acknowledged one does not — plus at-least-once resumption across a restart, end-to-end secrets by reference through a webhook, routing precedence, the console connector and the CC-11 bridge; Apache `tirbase-notify` unit tests cover the connectors, secret redaction and traversal rejection, backoff determinism and rotation arithmetic, and `tirbase-notify/tests/agpl_free.rs` walks `Cargo.lock` to prove the connector crate has no AGPL dependency. See `docs/alerting.md`.
- **GS1 EPCIS 2.0 adapter (CC-16):** Apache-2.0 `tirbase-epcis` turns a CC-14 signed ledger bundle into GS1 EPCIS 2.0, reading the bundle JSON with its own serde model so the crate has no AGPL edge — `tests/agpl_free.rs` walks `Cargo.lock` from `tirbase-epcis` and cross-checks its denylist against `LICENSING.md`. `map_bundle` maps `lot_registered` to a commissioning `ObjectEvent`, `lot_relocated` to a storing `ObjectEvent`, `lot_split`/`lot_merged` to `TransformationEvent`s (`disassembling`/`assembling`), `lot_repacked` to an `AggregationEvent` whose `parentID` is the new container, excursion detection/quarantine/disposition/resolution to inspecting/holding `ObjectEvent`s whose `disposition` follows the operator's decision (`release`→`active`, `hold`→`in_progress`, `reject`→`recalled`, `destroy`→`destroyed`), and `device_associated` to an `AssociationEvent`; ground truth it cannot express — hashes, actor DIDs, excursion reasons and samples, request/evidence digests, quantities and notes — is left to the ledger rather than smuggled into `extension`, and an event type with no mapping is reported through `MappedBundle::unsupported` instead of being half-filled. Identifiers stay honest: `eventID = urn:tirbase:ledger:<entry_id>`, lots are `urn:tirbase:lot:<id>` (an SGTIN only when the payload carries an `epc`), locations `urn:tirbase:location:<id>`, and the adapter never invents a company prefix. `json::to_json` emits sorted-key JSON-LD with the official EPCIS context, `xml::to_xml` emits the XSD element order in `urn:epcglobal:epcis:xsd:2`; every timestamp comes from the bundle (event payload times, ledger `recorded_est`, manifest `created_est`, overridable with `--creation-est`) and is rendered as UTC `+00:00`, so the same bundle always renders byte-identically and no clock is read. The official schema is vendored verbatim at `schema/epcis-json-schema.json` with its source, SHA-256 and GS1 disclaimer in `schema/NOTICE`, and `schema::Schema` validates against it with the draft-07 keywords that schema uses (local `$ref`, `propertyNames`, `additionalProperties`, `items`, `if`/`then`, `anyOf`/`allOf`/`oneOf`/`not`, `pattern`, `format`); the `tirbase-epcis` CLI writes JSON, XML or both from a bundle directory or file, verifies the Ed25519 signature against a caller-supplied key, prints the mapped counts and every unsupported entry to stderr, and exits `4` on a schema violation. Apache `tests/golden.rs` covers excursion, quarantine, disposition, packing and split fixtures byte-for-byte against committed outputs, schema validation of every golden document, run-to-run determinism, the `creationDate` override, and an unknown event type being reported; see `docs/epcis-adapter.md` for the mapping table, identifier scheme, time policy and unsupported fields.
- **Hash-chained lineage ledger and signed export (CC-14):** AGPL `tirbase_gateway::lineage_ledger` adds an append-only ledger in its own SQLite tables, where every `LedgerEntry` carries a sequence number, the previous entry's hash, a domain-separated entry hash (`TirBase/v1/LineageLedgerEntry` over the canonical sequence JSON), an EST timestamp, actor DID, device and lot ids, a lower-case event type from the published `EVENT_*` set, and a payload hash (`TirBase/v1/LineageLedgerPayload`) whose payload is stored alongside so the plaintext is re-derivable. `append` takes an `AppendRequest` (caller-supplied `entry_id`, `with_lot`/`with_device`) and is crash-safe and idempotent: the entry id is `UNIQUE`, a retried append returns `AppendOutcome::Duplicate` with the original entry and writes nothing — including after reopening the database — while reusing the id for a different payload is `LedgerError::Conflict`. `checkpoint(&key, est)` signs the raw 32-byte checkpoint hash with Ed25519 (`TirBase/v1/LineageLedgerCheckpoint`), is a no-op when the same signer re-checkpoints an unchanged head, and refuses a different signer at the same head. `verify(&trusted_dids, &resolver)` re-derives the chain and every checkpoint and reports `ViolationKind` — `SequenceGap`, `Duplicate`, `Reorder`, `PreviousHashMismatch`, `EntryHashMismatch`, `PayloadHashMismatch`, `Truncation`, `CheckpointForgery`, `CheckpointSignature`, `WrongSigner` — so a cut tail under a checkpoint, a swapped pair, a rewritten payload or actor, and a checkpoint signed by an unknown key all fail with a typed reason. `export` adds a detached-signature bundle: `export_bundle`/`BundleManifest`/`LedgerBundle`/`SignedBundle` with a format version, signer DID, range start/end and previous hash, entry count, root hash, the checkpoints covering the range, and optional attachments pinned by SHA-256; `write_to_dir`/`read_from_dir`/`read_attachments` handle the on-disk layout (`bundle.json`, hex `bundle.sig`, `attachments/`), and `verify_bundle`/`verify_bundle_hex` are pure functions over bytes with no database, filesystem or network access, reporting `BundleViolationKind` (`CountMismatch`, `RangeMismatch`, `Truncation`, `Duplicate`, `Reorder`, `PreviousHashMismatch`, `EntryHashMismatch`, `PayloadHashMismatch`, `RootHashMismatch`, `UntrustedSigner`, `SignatureInvalid`, `CheckpointInvalid`, `WrongSigner`, `AttachmentMissing`, `AttachmentHashMismatch`, `UnsupportedFormat`). `LineageLedger::import_bundle` re-verifies the bundle before writing, imports only missing entries and checkpoints, returns `ImportReport { imported, skipped }` so a re-import writes nothing, and refuses a sequence that local history already holds differently. The new offline command `tirbase-admin ledger verify --bundle FILE --signature FILE --trusted-key DID=HEX [--attachments DIR] [--json]` reads only those files, prints every failing kind with a remedy line, and exits non-zero on failure. AGPL `tests/lineage_ledger.rs` covers the contiguous domain-separated chain and checkpoint idempotence, retried/conflicting appends across a restart, payload and actor tampering, truncation and reordering, a wrong signer, the signed-bundle round trip through files with attachments, export → import → continue → idempotent re-import, and tampered bundles (edited entry, re-signed edited entry, duplicate, truncated-but-re-signed, wrong root and count, untrusted signer, missing and altered attachments); AGPL `tests/lineage_ledger_cli.rs` verifies a bundle offline from files alone, refuses an untrusted signer, fails a tampered on-disk bundle with typed reasons, and validates `--trusted-key` parsing.
- **Master data service (CC-15):** AGPL `tirbase_gateway::master_data` adds versioned master data for sites, locations, storage zones, trade items, parties, lots, devices and carriers, stored beside the rest of the gateway state in `primary.db`. A record is never overwritten: `MasterData::put` appends version *n+1* and closes the previous version's half-open effective range `[from, to)` at the new start, so `get(kind, id, at_est)` answers with the version in force at that instant and a change cannot alter what an earlier event meant; re-putting identical content returns the newest version unchanged and writes no audit row, revisions must take effect after the version they supersede, and `Retired` is terminal. Every create and revision lands in an append-only `master_data_audit` history (`history()`) with the actor, the reason, the new digest and the superseded digest/status. Validation covers identifiers (internal ids `[A-Za-z0-9][A-Za-z0-9._:-]{0,63}`, GLN-13 and GTIN-14 with GS1 mod-10 check digits), units (`QuantityUnit` allowlist; zone bands must be `FixedPointValue`s in registry unit 1 (degC) at exponent -1 with `min < max`), hierarchies (a location's parent must exist, be in the same site, still be referenceable, not close a cycle and stay within `MAX_LOCATION_DEPTH`; a zone's location must belong to the zone's site; device and lot locations likewise), and status transitions. Referential integrity is evaluated at the new version's effective time, so a record may reference a parent introduced at the same instant but not one that has not started or has been retired; `MasterDataError` reports the offending field for every rule. `resolve`/`resolve_lot`/`resolve_excursion` resolve an event's site, location, trade item, party, device, carrier and lot as of the event's own timestamp — filling the location from the observing device, the item from the lot's master-data record and the party from the site's operator — and report unresolved references in `missing` (store failures in `errors`, never as "missing"); `EventResolution::complete`/`require_complete` are the contract for every cold-chain event resolving its site, location, item and party. Calibration lives on the device record (`CalibrationAttributes`), with `calibration_status` returning `Valid`/`DueSoon`/`Expired`/`NotRequired` at a given instant, and `link_lot` mirrors a CC-12 lot identity (item, site, location, quantity, unit) into master data. Exports: digested canonical JSON (`export_json`), flat reporting CSV (`export_csv`) and EPCIS 2.0 vocabulary documents (`export_epcis` for `BizLocation`/`ReadPoint`) that express each site/location as an SGLN URN and count — rather than invent identifiers for — records without a GS1 id. AGPL `tests/master_data.rs` covers effective-date versioning, idempotent re-puts, illegal transitions, the audit history, a real lot and a real excursion resolving through a rename/operator change without the historical resolution or the stored domain record changing, every rejection path (bad GLN/GTIN, unknown parent, cross-site parent, self-parent, cycle, depth, cross-site zone, wrong units, unknown item, unit mismatch, retired reference, calibration pointing at a non-laboratory), calibration state over time, and the JSON/CSV/EPCIS exports.
- **Lineage ledger wiring (CC-14):** the ledger is no longer a standalone store: `tirbase_gateway::lineage_ledger::LedgerSink` (one `LineageLedger` plus the actor DID that gets attributed to events with no operator of their own) is attached to the CC-12 and CC-11 domains with `LotRegistry::with_ledger` and `ExcursionWorkflow::with_ledger`, so one shared sink makes the lot registry and the excursion workflow write a single chain. Registration appends `lot_registered` under `lot-registered:<lot_id>`, split/merge/repack append `lot_split`/`lot_merged`/`lot_repacked` under `lot-op:<operation_id>`, and the disposition and signed resolution append `excursion_dispositioned`/`excursion_resolved` under `excursion-disposition:<record_id>` and `excursion-resolution:<record_id>`. Each payload is derived from the stored domain object, so a replayed operation, a re-registered identity, or a retried disposition/resolution computes the same payload and lands as `AppendOutcome::Duplicate` rather than a second row or a `Conflict`; a replay also re-attempts the append, so a crash between the domain write and the ledger write is repaired by the retry instead of leaving a gap. `record_disposition` and `sign_resolution` return the stored record when the retry is identical instead of failing the state transition. A failed append surfaces as `LotError::Ledger`/`ExcursionError::Ledger` and leaves the committed domain write in place. AGPL `tests/lineage_ledger_wiring.rs` drives a real registration, split, repack and merge plus detect → quarantine → notify → signed disposition → signed resolution → close on one `primary.db`, then asserts the six-entry chain's order, stable entry ids, prev-hash links, payloads and actor, that every replay leaves the length unchanged, and that the chain verifies after a restart with a signed checkpoint and exports to a bundle that verifies offline.
- **Workflow pack configuration (CC-13):** Apache-2.0 `tirbase_demo::workflow` adds a versioned (`schema_version = 1`) `workflow.toml` document and validation for the excursion workflow it depends on (CC-11): detection `[thresholds]`, `[windows]` (assessment, quarantine cap, reporting and sampling), `[debounce]` (`min_findings`, window, cooldown), `[[notification.routes]]` (channel plus `quarantine_opened`/`disposition_recorded`/`resolution_signed`), `[[dispositions.codes]]` (code, kind, label), `[mkt]` (Arrhenius constants, sample cap) and `[lot]` metadata (kind, uom, label prefix). Every struct is `deny_unknown_fields` and every field is required, so a typo is a `missing field`/`unknown field` error; `WorkflowConfigError::field()` returns the offending field path for all of them, including schema errors. Semantic validation rejects wrong units (temperatures must be `unit_id = 1`, exponent -1), unordered bands, non-positive rates and durations, sampling/reporting/assessment/quarantine ordering, debounce bounds, zero MKT constants, unknown events, duplicate or malformed disposition codes with a missing kind, unknown lot kinds, an unsupported schema version, a `tirbase_min_version` newer than the build, and any secret-looking key. `load_pack` gains an optional `workflow` manifest entry and refuses a document whose `pack` is not the manifest id. The cold-room, reefer and pharma-gdp packs each ship a validated `workflow.toml`; the pharma config carries the GDP release vocabulary (`GDP-REL-001`, `GDP-BLK-002`, `GDP-REJ-006`, `GDP-DES-008`). AGPL `tirbase_gateway::excursion::config::ExcursionPolicy` turns a validated document into `DetectionThresholds`, `MktParameters`, windows, a `DebounceGate`, `PolicyRoute`s and disposition-code lookups, with `from_pack_dir`/`from_toml` and field-level errors, and `tirbase-demo` becomes a regular gateway dependency so the policy is available to the binary. Apache `tests/workflow_config.rs` proves all three packs load and validate, unknown/missing fields and every range/unit/version rule fail with the named field, and the committed documents hold no secrets; AGPL `tests/workflow_pack.rs` drives a complete nominal excursion for each pack (in-band samples stay quiet, out-of-band samples trigger, the debounce gate and assessment deadline come from the document, the configured channels receive the alert, the configured reject code is cited, and the closed record bridges into lot traceability), and shows that widening a band in the document changes detection without a rebuild. See `docs/src/operator-guide/workflow-configuration.md`.
- **Lot and batch traceability (CC-12):** AGPL `tirbase_gateway::lot` adds a persisted `LotRegistry` (its own SQLite tables in `primary.db`) storing lot/batch/repack identities with site, location, device links, a custody `TimeWindow`, ledger links (`applied_effect`, `excursion_record`, `security_event`, `external`) and quantity/unit, plus a directed lineage graph of `Split`/`Merge`/`Repack`/`Aggregate` edges. Every edge write refuses a cycle (including self-edges) with `LotError::CycleDetected` carrying the closing path, traversal is depth- and node-bounded and cycle-safe even for imported data, and `check_acyclic` validates stored graphs. `split`, `merge` and `repack` take a caller-supplied `operation_id` and record a digest of the request: replaying the same request returns `OperationOutcome::Replayed` and writes nothing, reusing the id for a different request is `LotError::Conflict`, quantity must balance (children sum to the parent, a merge equals the sum of its parents), and a consumed parent cannot be split or repacked again. `forward_trace`/`recall` return every affected lot with depth, path and location — grouped into `AffectedLocation`s — together with the affected ledger entries and any lots named only by an edge (`missing_links`), while `backward_trace`/`disposition_report` walk a lot back to its sources and their recorded dispositions. `query`, canonical digested `export_json` and `export_csv` are the read/hand-off surfaces. AGPL `tests/lot_traceability.rs` covers multi-level ancestry (split → repack → split → merge → aggregate), forward and backward recall including a mid-lineage disposition, cycle rejection on short, self and long loops, idempotent split/merge/repack replay, quantity conservation, missing links appearing and later resolving, and the query/export filters. `LotRegistry::link_excursion` is the CC-11 bridge: it copies a *final* (resolved or closed) `ExcursionRecord`'s own `lot_id`, decision, reason and decision time into the lot's disposition history, so a recall cites the signed resolution an operator recorded instead of a hand-built link; records still under quarantine, records that name no lot, records for an unregistered lot, and conflicting replays are refused, while an identical bridge is a no-op. The tests drive a real excursion through detect → quarantine → notify → reject → signed resolution → close, then assert the recall and disposition queries report that decision, and that unfinished or unattributable records never reach the lot registry.
- **Pharma GDP pack, excercise/drift classification and lot release gate (CC-10):** Apache-2.0 `tirbase-demo` grows optional GDP metadata: `pack.toml` may reference a `gdp.toml`, a `calibration.toml`, and a `qualification.toml`. `GdpDocument` declares the lot, mean kinetic temperature parameters (`GdpMkt`: activation energy, gas constant, reference temperature, reporting and sampling intervals), lane risk, calibration policy, and repeated `[[storage]]` rows that bind each storage class to a profile, labelled band, transient allowance, cumulative degree-second budget, and MKT limit. Loading validates the storage-to-profile binding, band ordering, budgets, sampling ≤ reporting, per-sensor calibration intervals against the policy, refusal of any certification claim in `qualification.toml`, and re-derives every `[[release]]` row in `expected/outcomes.toml` with `Pack::evaluate_release`. `Pack::excursion` derives an `ExcursionSummary` from the *accepted* timeline only (`classify_excursion`: out-of-band seconds, time-weighted degree-seconds in 0.1 °C units, refusals), so a transient excursion inside the storage class's allowance is told apart from cumulative drift that crosses it or refuses a step. `Pack::evaluate_release` applies a fixed gate order — calibration expiry, sensor failure, lane risk, MKT, excursion class — so an expired calibration always blocks release, and returns `ReleaseDisposition`/`ReleaseDecision` with codes `GDP-REL-001`, `GDP-BLK-002`…`GDP-BLK-005`, `GDP-REJ-006`, `GDP-REJ-007` aligned with CC-11. The new `tirbase-demo/pharma-gdp/` pack is data only: three storage-class profiles (2–8 °C, frozen, controlled room) sharing five parameters, two controller register maps, four calibration records, a DQ/IQ/OQ/PQ checklist that states `certification = "none"` with an explicit evidence boundary, three S2 scenarios (transient excursion, cumulative drift, sensor failure), `expected/outcomes.toml`, and a `sim/config.toml` room model with hourly MKT reporting. Apache `tests/pharma_gdp_pack_structure.rs` covers structure, units, MKT parameters, calibration ordering, the no-certification rule, release re-derivation, and negative cases; AGPL `tirbase-gateway/tests/pharma_gdp_pack.rs` installs all three committed signatures, refuses a tampered profile, drives every scenario, and proves the transient excursion is held while cumulative drift is rejected and an expired calibration blocks release. See `tirbase-demo/pharma-gdp/docs/README.md`.
- **Reefer/container pack and trip quarantine (CC-09):** Apache-2.0 `tirbase-demo` grows optional trip metadata: `pack.toml` may reference a `trip.toml`, and `TripDocument`/`TripLocation`/`TripDisposition`/`ExpectedTripOutcome` let a transport pack declare container and trailer identity, trip id, route, cargo band, current location, and a `max_door_open_secs` excursion rule. The new `tirbase-demo/reefer/` pack is data only: six-parameter reefer profile (ambient, setpoint, door, power state, defrost, compressor), two controller register maps, `trip.toml` for container `MSCU1234567`/trailer `TRL-0081`/trip `TRIP-2026-1115-0042`, five S1/S2 scenarios (door open in transit, power loss, ambient spike, sensor dropout, setpoint tampering), `expected/outcomes.toml` with the quarantine disposition, and a `sim/config.toml` lumped-capacitance thermal model with diurnal ambient variation. See `tirbase-demo/reefer/docs/README.md`.
- **Data-only pack framework and cold-room pack (CC-08):** Apache-2.0 `tirbase_demo` now loads a versioned pack: `pack.toml` (schema version 1) with manifest identity, licence, device class, profile/register-map/scenario/docs/expected/sim references, plus `PackManifest`, `PackScenario`, `ScenarioStep`, `PackExpectedOutputs`, and `load_pack`. - **MQTT sensor bridge (CC-07):** AGPL `tirbase_drivers::mqtt` adds a TLS-only `MqttBridgeClient` over the existing rustls transport. It sends per-device username/password credentials in CONNECT (redacted from `Debug`), subscribes only to an exact-match `MqttTopicAllowlist` (wildcards require `with_wildcards`, never the default), accepts a documented six-field `key=value` payload schema (`v`, `device`, `seq`, `ts`, `temp_mc`, `rh_cp`) decoded to `FixedPointValue`, ACKs QoS 1 PUBLISH before validation, rejects packets from the remaining-length header before allocating, and applies a bounded per-device `MqttReplayGuard` (strictly increasing `seq` plus a timestamp window). The bridge builds its own `rustls::ClientConfig` from a CA-root-only `MqttTlsTrust`, so certificate verification has no bypass path, and every connect/read derives a deadline from a caller-supplied clock so a broker outage fails within the configured budget. Apache-2.0 `tirbase_driver_api::mqtt_codec` gains credential CONNECT, SUBSCRIBE/SUBACK, DISCONNECT, and UTF-8 field validation. Loopback-TLS-broker tests plus the extended `mqtt_frame` fuzz target cover valid, invalid, oversized, replayed, non-allowlisted, untrusted-certificate, and silent-broker cases. See `docs/drivers/mqtt_sensor_bridge.md`.
- **BLE probes (CC-06):** Apache-2.0 `tirbase_driver_api::ble_gatt` parses BLE advertising structures, validates a configurable service/temperature/humidity UUID map, and decodes the SIG Environmental Sensing (`0x181A`/`0x2A6E`/`0x2A6F`) fixed-point payloads with typed rejection of truncated, oversized, and physically impossible values. AGPL `tirbase_drivers::ble` defines the bounded `BleCentral` radio boundary and a native `btleplug` adapter behind the `ble-radio` feature; AGPL `tirbase_guard::ble` owns a step-driven `GuardBleProbe` with explicit scan/connect/read timeouts, capped exponential reconnect backoff, and counters-only health. Pairing material is in-memory only, zeroized, redacted from `Debug`, and never logged or serialized. `tirbase_sim::SimBleGattPeripheral` injects link drops, connect failures, absent peripherals, and malformed GATT payloads; guard tests prove reconnection, bounded retries, custom UUID maps, and no secret in debug/errors/metrics. See `docs/drivers/ble_probes.md`.
- **4–20 mA transducer driver (CC-05):** Apache-2.0 `tirbase_driver_api::current_loop` provides validated 2–16 point ADC-count→current calibration, integer piecewise-linear conversion, unit-registry `FixedPointValue` output clamped to the engineering span, and a bounded fault detector classifying open loop, under-range, over-range, noise, and stuck value with range faults taking priority. AGPL `tirbase_guard::current_loop` adds a versioned JSON `CurrentLoopCalibrationStore` with atomic temp-file + rename writes, load-time re-validation, and `detect_drift` against the persisted baseline. `tirbase_sim::Sim4To20MaAdc` now emits 12-bit ADC counts and injects open-loop, under-range, over-range, noise, and stuck faults. - **BACnet/IP read bridge (CC-04):** Apache-2.0 `tirbase_driver_api::bacnet_codec` implements bounded BVLC/NPDU/APDU framing, Who-Is/I-Am discovery, and ReadProperty for analog/binary inputs and values, with typed errors for rejects, aborts, error PDUs, oversized frames, and segmented/routed traffic. AGPL `tirbase_drivers::bacnet` provides a feature-gated (`bacnet-ip`) UDP client with clamped retries and clock-bounded deadlines; `BacnetIpClient::write_property` and `encode_write_property` always return `BacnetError::WriteRejected` before any I/O. ### Fixed
- **Demo-pack launcher checks timed out on build-lock contention:** each pack's `run.sh` spawned a nested `cargo test`, which competes with the running `cargo test` for the build directory and pushed the launchers past their 120 s budget (129 s+ even on an idle tree). Launchers now run a prebuilt test binary when the caller provides one (`TIRBASE_DEMO_TEST_BIN`, set by the pack tests to their own executable) and fall back to cargo for standalone use, the pack tests run their launchers one at a time instead of six in parallel, and they assert that the checks really executed (`test result: ok`, never `0 passed`) so the faster path cannot pass by skipping work.
- **Cumulative drift window double-counted one segment:** Stage 13 summed the window from the newest sample instead of the oldest, adding a phantom `|oldest - newest|` term that rejected legal step sequences early. The window now sums consecutive deltas only, so a slow ramp is rejected exactly when it crosses the profile's budget. Covered by the cold-room `S2_slow_ramp` scenario.
- **Stage 16 dwell/min-off summary read the post-write state:** `SqliteStage16Store` upserted `target_state` before reading the previous value, so `value_changed` and `is_bool_deactivation` were always false and the `drift_rate_summary` timing columns never advanced. The previous value is now read before the write, restoring dwell and min-off interlocks (cold-room `S2_door_abuse`, `S2_compressor_short_cycling`, `S1_defrost_manipulation`).
- **CRDT array/list convergence:** `CrdtEngine` now stores JSON arrays as real Automerge lists (RGA-capable) and projects list values as JSON arrays on read/merge/projection, fixing a defect exposed by real-mesh concurrent list insertion proof.
