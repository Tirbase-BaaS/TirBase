## [Unreleased]

### Added
- **Pharma GDP pack, excercise/drift classification and lot release gate (CC-10):** Apache-2.0 `tirbase-demo` grows optional GDP metadata: `pack.toml` may reference a `gdp.toml`, a `calibration.toml`, and a `qualification.toml`. `GdpDocument` declares the lot, mean kinetic temperature parameters (`GdpMkt`: activation energy, gas constant, reference temperature, reporting and sampling intervals), lane risk, calibration policy, and repeated `[[storage]]` rows that bind each storage class to a profile, labelled band, transient allowance, cumulative degree-second budget, and MKT limit. Loading validates the storage-to-profile binding, band ordering, budgets, sampling ≤ reporting, per-sensor calibration intervals against the policy, refusal of any certification claim in `qualification.toml`, and re-derives every `[[release]]` row in `expected/outcomes.toml` with `Pack::evaluate_release`. `Pack::excursion` derives an `ExcursionSummary` from the *accepted* timeline only (`classify_excursion`: out-of-band seconds, time-weighted degree-seconds in 0.1 °C units, refusals), so a transient excursion inside the storage class's allowance is told apart from cumulative drift that crosses it or refuses a step. `Pack::evaluate_release` applies a fixed gate order — calibration expiry, sensor failure, lane risk, MKT, excursion class — so an expired calibration always blocks release, and returns `ReleaseDisposition`/`ReleaseDecision` with codes `GDP-REL-001`, `GDP-BLK-002`…`GDP-BLK-005`, `GDP-REJ-006`, `GDP-REJ-007` aligned with CC-11. The new `tirbase-demo/pharma-gdp/` pack is data only: three storage-class profiles (2–8 °C, frozen, controlled room) sharing five parameters, two controller register maps, four calibration records, a DQ/IQ/OQ/PQ checklist that states `certification = "none"` with an explicit evidence boundary, three S2 scenarios (transient excursion, cumulative drift, sensor failure), `expected/outcomes.toml`, and a `sim/config.toml` room model with hourly MKT reporting. Apache `tests/pharma_gdp_pack_structure.rs` covers structure, units, MKT parameters, calibration ordering, the no-certification rule, release re-derivation, and negative cases; AGPL `tirbase-gateway/tests/pharma_gdp_pack.rs` installs all three committed signatures, refuses a tampered profile, drives every scenario, and proves the transient excursion is held while cumulative drift is rejected and an expired calibration blocks release. See `tirbase-demo/pharma-gdp/docs/README.md`.
- **Reefer/container pack and trip quarantine (CC-09):** Apache-2.0 `tirbase-demo` grows optional trip metadata: `pack.toml` may reference a `trip.toml`, and `TripDocument`/`TripLocation`/`TripDisposition`/`ExpectedTripOutcome` let a transport pack declare container and trailer identity, trip id, route, cargo band, current location, and a `max_door_open_secs` excursion rule. Loading validates the ISO 6346 container number, coordinate range, cargo band ordering, and the door parameter, and derives the trip disposition from the scenario's *accepted* door timeline (`longest_door_open_secs`, `Pack::door_open_secs`, `Pack::derived_trip_disposition`), refusing a pack whose expected `[trip]` disposition or door-open seconds disagree with the accepted steps. The new `tirbase-demo/reefer/` pack is data only: six-parameter reefer profile (ambient, setpoint, door, power state, defrost, compressor), two controller register maps, `trip.toml` for container `MSCU1234567`/trailer `TRL-0081`/trip `TRIP-2026-1115-0042`, five S1/S2 scenarios (door open in transit, power loss, ambient spike, sensor dropout, setpoint tampering), `expected/outcomes.toml` with the quarantine disposition, and a `sim/config.toml` lumped-capacitance thermal model with diurnal ambient variation. Apache `tests/reefer_pack_structure.rs` covers structure, units, trip derivation, and negative cases; AGPL `tirbase-gateway/tests/reefer_pack.rs` installs the committed signature, drives every scenario, asserts the 300 s/120 s quarantine, and proves the excursion record booked in the cold-chain store plus the guard's persisted door and deactivation state survive a power loss and still enforce min-off after restart. See `tirbase-demo/reefer/docs/README.md`.
- **Data-only pack framework and cold-room pack (CC-08):** Apache-2.0 `tirbase_demo` now loads a versioned pack: `pack.toml` (schema version 1) with manifest identity, licence, device class, profile/register-map/scenario/docs/expected/sim references, plus `PackManifest`, `PackScenario`, `ScenarioStep`, `PackExpectedOutputs`, and `load_pack`. Loading validates the schema version, id/directory identity, contained relative paths (no traversal or symlink escape), profile/scenario parameter and unit agreement, replay references, and one-to-one expected-output coverage with derived dispositions and actuation counts; `safe_pack_path` is public. The new `tirbase-demo/cold-room/` pack is data only: `profiles/cold_room.toml` (setpoint range/rate/drift, door-open dwell and min-off, defrost dwell/min-off and termination-temperature bounds, compressor min-off), two controller register maps with pinned units, six S1/S2/S3 scenarios, `expected/outcomes.toml`, `sim/config.toml`, `run.sh`, and docs with intended use, assumptions, expected defended output, and non-goals. Apache `tests/cold_room_pack_structure.rs` proves the structure, units, scenario/expected consistency, and data-only rule; AGPL `tirbase-gateway/tests/cold_room_pack.rs` installs the committed PA-signed profile and drives every scenario through Stages 0–16, asserting the pack's own expected dispositions, defense stage, and actuation counts. See `tirbase-demo/cold-room/docs/README.md`.
- **MQTT sensor bridge (CC-07):** AGPL `tirbase_drivers::mqtt` adds a TLS-only `MqttBridgeClient` over the existing rustls transport. It sends per-device username/password credentials in CONNECT (redacted from `Debug`), subscribes only to an exact-match `MqttTopicAllowlist` (wildcards require `with_wildcards`, never the default), accepts a documented six-field `key=value` payload schema (`v`, `device`, `seq`, `ts`, `temp_mc`, `rh_cp`) decoded to `FixedPointValue`, ACKs QoS 1 PUBLISH before validation, rejects packets from the remaining-length header before allocating, and applies a bounded per-device `MqttReplayGuard` (strictly increasing `seq` plus a timestamp window). The bridge builds its own `rustls::ClientConfig` from a CA-root-only `MqttTlsTrust`, so certificate verification has no bypass path, and every connect/read derives a deadline from a caller-supplied clock so a broker outage fails within the configured budget. Apache-2.0 `tirbase_driver_api::mqtt_codec` gains credential CONNECT, SUBSCRIBE/SUBACK, DISCONNECT, and UTF-8 field validation. Loopback-TLS-broker tests plus the extended `mqtt_frame` fuzz target cover valid, invalid, oversized, replayed, non-allowlisted, untrusted-certificate, and silent-broker cases. See `docs/drivers/mqtt_sensor_bridge.md`.
- **BLE probes (CC-06):** Apache-2.0 `tirbase_driver_api::ble_gatt` parses BLE advertising structures, validates a configurable service/temperature/humidity UUID map, and decodes the SIG Environmental Sensing (`0x181A`/`0x2A6E`/`0x2A6F`) fixed-point payloads with typed rejection of truncated, oversized, and physically impossible values. AGPL `tirbase_drivers::ble` defines the bounded `BleCentral` radio boundary and a native `btleplug` adapter behind the `ble-radio` feature; AGPL `tirbase_guard::ble` owns a step-driven `GuardBleProbe` with explicit scan/connect/read timeouts, capped exponential reconnect backoff, and counters-only health. Pairing material is in-memory only, zeroized, redacted from `Debug`, and never logged or serialized. `tirbase_sim::SimBleGattPeripheral` injects link drops, connect failures, absent peripherals, and malformed GATT payloads; guard tests prove reconnection, bounded retries, custom UUID maps, and no secret in debug/errors/metrics. See `docs/drivers/ble_probes.md`.
- **4–20 mA transducer driver (CC-05):** Apache-2.0 `tirbase_driver_api::current_loop` provides validated 2–16 point ADC-count→current calibration, integer piecewise-linear conversion, unit-registry `FixedPointValue` output clamped to the engineering span, and a bounded fault detector classifying open loop, under-range, over-range, noise, and stuck value with range faults taking priority. AGPL `tirbase_guard::current_loop` adds a versioned JSON `CurrentLoopCalibrationStore` with atomic temp-file + rename writes, load-time re-validation, and `detect_drift` against the persisted baseline. `tirbase_sim::Sim4To20MaAdc` now emits 12-bit ADC counts and injects open-loop, under-range, over-range, noise, and stuck faults. Simulator-backed tests prove reference-vector calibration, fault distinguishability, clamping, and calibration survival across restart. See `docs/drivers/current_loop_4_20ma.md`.
- **BACnet/IP read bridge (CC-04):** Apache-2.0 `tirbase_driver_api::bacnet_codec` implements bounded BVLC/NPDU/APDU framing, Who-Is/I-Am discovery, and ReadProperty for analog/binary inputs and values, with typed errors for rejects, aborts, error PDUs, oversized frames, and segmented/routed traffic. AGPL `tirbase_drivers::bacnet` provides a feature-gated (`bacnet-ip`) UDP client with clamped retries and clock-bounded deadlines; `BacnetIpClient::write_property` and `encode_write_property` always return `BacnetError::WriteRejected` before any I/O. AGPL `tirbase_guard::bacnet` owns the endpoint as `GuardBacnetReader` and adds `BacnetPoller`, a bounded step scheduler (≤64 points, clamped interval, one read per point per due round, per-point failures) that never spawns a thread or reads a clock. A loopback `BacnetSimServer` plus recorded PDUs and a `bacnet_ip` fuzz target cover the bridge without a physical device. See `docs/drivers/bacnet_ip.md`.
- **Modbus thermostat profiles (CC-03):** Apache-2.0 `tirbase_driver_api::thermostat` defines validated six-field thermostat profiles, typed mode/fan codes, and two original register maps (`profiles/thermostat_generic_{a,b}.register-map.toml`). AGPL `tirbase_drivers::thermostat` installs them on either Modbus client with read/write helpers and bounded-timeout retries. Modbus exception PDUs now surface as `DriverError::Exception { function_code, exception_code }`, and RTU responses are length-aware so exception frames decode correctly. See `docs/drivers/thermostat_modbus.md`.
- **DS18B20 1-Wire driver (CC-02):** Apache-2.0 codec in `tirbase-driver-api::ds18b20` (reset/presence, Convert T, Read Scratchpad, CRC-8, resolution/temperature decode, Match ROM), AGPL bus/sensor runtime in `tirbase_drivers::onewire` with typed health/fault state, a guard-owned bounded `w1_slave` sysfs transport (`tirbase_guard::onewire`) using `poll(2)` deadlines, and deterministic `SimOneWireBus` fault injection for bad CRC, short reads, disconnect, impossible/power-on temperatures, contention, timeouts, and conversion timing. Recorded-frame and FIFO bounded-read tests included; see `docs/drivers/ds18b20.md`.
- **Driver API split and vendor conformance kit (CC-01):** the pure Modbus frame codec moves into the Apache-2.0 `tirbase-driver-api` crate, which now publishes `conformance` (round-trip, bounded time, typed errors, scaling, word order, no-I/O checks) and ships an Apache-2.0 vendor example with register map, golden frames, and tests. `tirbase-drivers` re-exports the API and codec under deprecated compatibility paths. A dependency test walks `Cargo.lock` from `tirbase-driver-api` to prove the graph is AGPL-free. See `docs/driver-api.md`.
- **Operator console shell (F-09):** Apache-2.0 React/Vite console under `console/` consuming only the generated OpenAPI SDK. Includes a shared design-system workspace package, tenant/site switching, tables, filters, forms, empty/error states, keyboard focus management, English/Spanish localization hooks, timezone-aware formatting, a licence-boundary check, and Playwright tests for the shell plus one journey per vertical. CI job `operator-console` builds and tests it.
- **Vertical admin API, SDKs, webhooks and CLI (F-08):** tenant-scoped resources under `/admin/cold-chain`, `/admin/pos` and `/admin/venues` (sites/readings, orders/lines, venues/gates) with cursor pagination, `idempotency_key` replay, revisioned objects and OpenAPI 3.1 documentation (`docs/api/gateway-admin-openapi.yaml`). Generated Apache-2.0 TypeScript and Python clients (`sdk/typescript`, `sdk/python`) are produced by `scripts/generate-gateway-sdk.mjs`; `scripts/check-openapi-compat.mjs` plus `docs/api/openapi-compat.lock.json` fail CI on unversioned breaking spec changes. HMAC-SHA256 webhooks (`tirbase-gateway/src/webhooks.rs`) persist deliveries, retry with exponential backoff, and reject replayed delivery ids. AGPL admin CLI commands `vertical` and `webhook` manage the same resources and endpoints.

### Fixed
- **Demo-pack launcher checks timed out on build-lock contention:** each pack's `run.sh` spawned a nested `cargo test`, which competes with the running `cargo test` for the build directory and pushed the launchers past their 120 s budget (129 s+ even on an idle tree). Launchers now run a prebuilt test binary when the caller provides one (`TIRBASE_DEMO_TEST_BIN`, set by the pack tests to their own executable) and fall back to cargo for standalone use, the pack tests run their launchers one at a time instead of six in parallel, and they assert that the checks really executed (`test result: ok`, never `0 passed`) so the faster path cannot pass by skipping work.
- **Cumulative drift window double-counted one segment:** Stage 13 summed the window from the newest sample instead of the oldest, adding a phantom `|oldest - newest|` term that rejected legal step sequences early. The window now sums consecutive deltas only, so a slow ramp is rejected exactly when it crosses the profile's budget. Covered by the cold-room `S2_slow_ramp` scenario.
- **Stage 16 dwell/min-off summary read the post-write state:** `SqliteStage16Store` upserted `target_state` before reading the previous value, so `value_changed` and `is_bool_deactivation` were always false and the `drift_rate_summary` timing columns never advanced. The previous value is now read before the write, restoring dwell and min-off interlocks (cold-room `S2_door_abuse`, `S2_compressor_short_cycling`, `S1_defrost_manipulation`).
- **CRDT array/list convergence:** `CrdtEngine` now stores JSON arrays as real Automerge lists (RGA-capable) and projects list values as JSON arrays on read/merge/projection, fixing a defect exposed by real-mesh concurrent list insertion proof.
