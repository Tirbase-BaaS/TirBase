# DS18B20 1-Wire Temperature Driver (CC-02)

Reference DS18B20 driver split along the CC-01 licence boundary:

- **Pure codec (Apache-2.0):** `tirbase_driver_api::ds18b20` (`tirbase-driver-api/src/ds18b20.rs`).
- **Runtime bus/sensor (AGPL-3.0-only):** `tirbase_drivers::onewire` (`Ds18b20Bus`, `Ds18b20Sensor`, `Ds18b20Codec`).
- **Guard transport (AGPL-3.0-only):** `tirbase_guard::onewire` (`W1SysfsBus`, `GuardOneWireSensor`).
- **Simulator (AGPL-3.0-only):** `tirbase_sim::SimOneWireBus`.

## Bus transactions

The driver emits standard 1-Wire ROM/function frames over [`Ds18b20Bus`]:

| Frame | Bytes | Purpose |
|---|---|---|
| Skip ROM + Convert T | `CC 44` | Convert all devices on the bus |
| Match ROM + Convert T | `55 <8-byte ROM> 44` | Convert one addressed device |
| Skip ROM + Read Scratchpad | `CC BE` | Read 9 scratchpad bytes |
| Match ROM + Read Scratchpad | `55 <8-byte ROM> BE` | Read one addressed device |

The bus trait exposes reset/presence, write, bounded read, and the resolution's
conversion wait. The sensor performs reset → Convert T → wait → reset → Read
Scratchpad → CRC → decode.

### Scratchpad layout

| Byte | Field |
|---:|---|
| 0–1 | Temperature, signed little-endian, 0.0625 °C LSB |
| 2 | `TH` alarm high |
| 3 | `TL` alarm low |
| 4 | Configuration register (resolution bits 6:5) |
| 5–7 | Reserved (`FF 0C 10` on the datasheet part; `FF 0E 10` in the recorded frame below) |
| 8 | Dallas/Maxim CRC-8 over bytes 0–7 |

CRC-8 uses the reflected polynomial `0x8C`, init `0`, no final XOR (equivalent
to the common `0x31` non-reflected form). Recorded frame:

```text
72 01 4b 46 7f ff 0e 10 57 : crc=57 YES
72 01 4b 46 7f ff 0e 10 57 t=23125
```

`0x0172` = 370 counts = **23.125 °C**.

## Temperature and resolution

The decoded value is `raw * 625` with exponent `-4` and `UNIT_DEG_C`, i.e.
millidegrees Celsius. The resolution quantises the low bits:

| Resolution | Config bits | Mask | Conversion time |
|---|---:|---:|---:|
| 9-bit | `0x00` | `0xFFF8` | 94 ms |
| 10-bit | `0x20` | `0xFFFC` | 188 ms |
| 11-bit | `0x40` | `0xFFFE` | 375 ms |
| 12-bit | `0x60` | `0xFFFF` | 750 ms |

Conversion waits use the datasheet maximum for the configured resolution.
`0x0550` (85.0 °C) is the power-on-reset value and is rejected rather than
reported as a measurement.

## Faults

| Fault | Detection |
|---|---|
| `Disconnected` | No presence pulse / missing sysfs node |
| `BadCrc { computed, received }` | CRC-8 mismatch |
| `ShortScratchpad { len }` | Fewer than 9 bytes |
| `PowerOnReset` | Raw `0x0550` |
| `ImpossibleTemperature { raw }` | Raw outside `-880..=2000` (−55…125 °C) |
| `BusContention` | Bus held low by another master |
| `Timeout { operation }` | Bounded transport deadline expired |
| `ConversionIncomplete` | Scratchpad read before conversion finished |
| `Protocol(String)` | Malformed frame/command or unparseable sysfs document |

Bad CRC and all other faults are returned as typed errors; none panic. The
sensor records health after every read: `present`, `last_fault`,
`consecutive_failures`, `successful_reads`, and `last_temperature`
(`Ds18b20Health`). A successful read clears `last_fault` and the failure count.

## Linux `w1_therm` transport

`W1SysfsBus` targets `/sys/bus/w1/devices/<rom>/w1_slave`. It does not drive
GPIO itself; the kernel `w1_therm` driver owns reset/presence and conversion.
The guard transport:

- opens the file with `O_NONBLOCK`;
- waits with `poll(2)` bounded by a caller-supplied timeout and monotonic clock
  (`MonotonicMillisFn`), never an unbounded blocking read;
- rejects documents larger than `MAX_W1_SLAVE_BYTES` (4096);
- treats a missing node as `Disconnected`;
- performs no conversion wait (`w1_therm` converts inside `read(2)`).

`GuardOneWireSensor` wraps the transport and a `Ds18b20Sensor`, exposing
`read_temperature`, `health`, `fault_state`, and `is_healthy`.

```rust
use std::sync::Arc;
use std::time::Duration;
use tirbase_guard::onewire::GuardOneWireSensor;
use tirbase_drivers::onewire::Ds18b20Resolution;

let clock = Arc::new(|| 0u64); // caller-supplied monotonic millis
let mut sensor = GuardOneWireSensor::open(
    "/sys/bus/w1/devices/28-000006b4a69b",
    Duration::from_millis(250),
    clock,
    None,
    Ds18b20Resolution::Bits12,
)?;
let temperature = sensor.read_temperature()?;
```

## Simulator and recorded frames

`SimOneWireBus` is a deterministic, virtual-time bus for tests:

```rust
use tirbase_sim::SimOneWireBus;
use tirbase_drivers::onewire::{Ds18b20Sensor, Ds18b20Resolution};

let bus = SimOneWireBus::new(0x0191, Ds18b20Resolution::Bits12); // 25.0625 °C
let mut sensor = Ds18b20Sensor::new(bus, None, Ds18b20Resolution::Bits12);
let temperature = sensor.convert_and_read()?; // 250625 × 10⁻⁴ °C
```

Faults are injectable with `set_present`, `set_short_read`, `set_bad_crc`,
`set_temperature_raw`, `set_contention`, `set_timeout`, and
`set_conversion_required`. `SimOneWireBus::from_w1_slave` replays a recorded
`w1_slave` document. The simulator records command frames, conversion waits, and
virtual elapsed time for assertions.

## Limits

- One sensor per `w1_slave` file; multi-drop discovery/enumeration is not
  implemented (the kernel enumerates devices and ROM IDs).
- `TH`/`TL` and the alarm search command are not interpreted.
- Parasite-power strong pull-up is not controlled; an externally powered bus is
  assumed.
- Conversion waits are conservative datasheet maxima, not measured completion.
- `w1_therm` conversion timing is kernel-owned; the guard timeout must exceed
  the configured resolution's conversion time.
