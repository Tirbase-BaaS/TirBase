## Residual blockers (evidence-backed, genuinely hardware/environment-gated or out-of-scope for CI proof)

## Change summary

- Added the `parity-probe` feature, `tirbase-core/src/parity_probe.rs` (`canonical_state_hash`, `emit_cross_build_parity_hash`), the WASM export `core_cross_build_parity_hash`, and `scripts/cross-build-parity.sh`; wired as a CI step (WS8, `ec509f4`).
- Fixed production CRDT array/list handling to use real Automerge lists (RGA-capable) for JSON array writes/projections. This is what makes concurrent list-insertion preservation over the real mesh provable at all (WS8, `ec509f4`).
- **Removed the per-receiver RGA override in `crdt/verify.rs`** (WS8, `ec509f4`). The override rewrote a receiving peer's list order to put the incoming element first whenever the incoming Delta had the higher Lamport clock. That rule is applied only on the receiving side, so after both peers had merged each had applied it in a different direction and the lists could never converge. `verify` now records the prediction mismatch (`report.divergences += 1`) and logs `[CRDT] RGA DIVERGENCE … preserving Automerge-convergent order (no override)`, letting the Automerge merge result stand. The new convergence test `api::real_mesh_tests::two_devices_concurrent_list_insertions_preserved_over_real_mesh` covers the concurrent-insert case that this override used to break.
- Per-table Automerge documents and table-scoped compaction landed in **WS7**, commit `19bcca0` (same content as the pre-rewrite `cb9ed1b`) — not in WS8. WS8's `crdt/mod.rs` change builds on them (list storage and `parity_state_bytes` per table).
- Added `tests::properties::prop_20_sequence_covers_renewal_and_termination_events` and reconciled the `properties.rs` gap annotations for Properties 1, 2/3/4, 5/14 and 20.
- Reconciled `README.md`, `CLAIMS.md` (CLAIM-G1.11 plus CLAIM-59.1–59.7), `docs/traceability-matrix.md` and `tirbase-core/tests/README.md` to the now-proven status.

### Finding from target 5: which replay path is actually wired

The first attempt at target 5 disabled `SideCarLedger::replay_sidecar` (the ledger-level async
method in `migration/sidecar.rs`) and **the test still passed** (0.23s). The mesh path does not go
through it: `CoreHandle`'s corrected-migration flow calls
`SchemaMigrationEngine::resume_pending_sidecar_replays` → `replay_corrupted_windows`
(`migration/mod.rs`). Disabling that native function is what fails the test. So the ledger-level
`replay_sidecar` is the standalone/WASM entry point, not the production mesh caller — worth knowing
before anyone cites it as the proof's wiring point.
